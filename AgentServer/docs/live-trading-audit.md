# 实盘可操作审查报告

> 从实盘交易的角度，系统审查现有代码的所有缺口和优化点

## 🔴 P0 - 不做就不能实盘（必须修复）

### 1. Scanner硬编码量脉，数据源未打通
**现状**: `_fetch_realtime_batch()` 硬编码 `LiangMaiClient`，必盈适配器写好了但Scanner根本没用  
**问题**: 量脉IP绑定问题频发 → 扫描器随时瘫痪  
**修复**: Scanner通过 `DataSourceRouter` 获取行情，不再直接依赖任何单一数据源  
**影响**: 量脉挂了整个扫描就停了

### 2. 持仓/订单纯内存，断电即丢
**现状**: `SimulatedBroker` 的 Account/Position/Order 全在内存里  
**问题**: 服务重启、进程崩溃、服务器断电 → 所有持仓和交易记录丢失  
**修复**: 持仓和订单持久化到MongoDB，启动时恢复  
**影响**: 实盘必须有持久化，否则无法对账

### 3. 没有订单状态机
**现状**: `place_order()` 是同步撮合，买入即成交，无pending/rejected/canceled状态  
**问题**: 真实券商是异步的(下单→待报→已报→部分成交→全部成交)，当前模型无法对接  
**修复**: 实现订单状态机(pending→submitted→partial→filled/canceled/rejected)  
**影响**: 不改就无法对接QMT/掘金

### 4. 没有交易确认/对账机制
**现状**: 下单后直接算成交，没有成交回报、没有对账  
**问题**: 实盘可能出现废单、部成、撤单等情况，当前代码完全忽略  
**修复**: 增加成交回报处理 + 盘后对账（本地持仓 vs 券商持仓）

## 🟡 P1 - 不做则实盘风险很大（强烈建议）

### 5. 止损只在扫描循环检查，不是实时监控
**现状**: `_check_positions()` 在每轮扫描(5分钟)才检查一次止损  
**问题**: 5分钟内股价可能暴跌5%+，来不及止损  
**修复**: 
- 方案A: 注册券商止损单(如果券商支持)
- 方案B: 行情推送触发(WebSocket) → 立即检查
- 方案C: 至少把扫描间隔缩到30秒（必盈免费版可行）

### 6. 缺少涨停买不进/跌停卖不出的撮合逻辑
**现状**: broker.py有涨跌停判断但仅限限价单，市价单(实盘主力)没判断  
**问题**: 涨停板扫货 → 实际买不进 → 策略回测虚高  
**修复**: 市价买入涨停股 → rejected；市价卖出跌停股 → rejected

### 7. 没有仓位管理策略
**现状**: `_execute_signals()` 固定 `available_cash * 0.3` 买入  
**问题**: 
- 3只信号股各买30% → 满仓(90%)
- 没有根据信号强度/策略置信度分配仓位
- 没有动态仓位控制(行情好加仓/差减仓)  
**修复**: 实现 `PositionSizer` 模块，按策略/信号强度/波动率分配仓位

### 8. 缺少实盘滑点模拟
**现状**: 固定0.1%滑点  
**问题**: 涨停板追单实际滑点可能3-5%，大量成交滑点1-2%  
**修复**: 动态滑点 = f(流动性, 委托量/成交量, 涨跌状态)

### 9. 没有盘中风控熔断
**现状**: PreBuyRiskChecker 只有买入前检查，没有盘中熔断  
**问题**: 
- 没有单日最大亏损熔断（亏5%应停止交易）
- 没有连续止损熔断（连亏3次应暂停）
- 没有异常行情熔断（指数暴跌应全部清仓）
**修复**: 在 `_scan_loop()` 每轮加入 `CircuitBreaker` 检查

### 10. 前端没有实盘操作入口
**现状**: 实盘交易页只有预选池+持仓+时间线，没有：
- 下单按钮(手动买/卖)
- 撤单功能
- 仓位调整
- 风控开关
- 券商切换  
**修复**: 增加"交易操作"区域，至少支持手动买卖和撤单

## 🟢 P2 - 有了更好，提升实盘效率

### 11. DailyScheduler盘中只跑一次
**现状**: `run_intraday()` 获取一次行情+检查一次风控就结束了，没有循环  
**问题**: 应该9:30-15:00持续运行，每30秒-5分钟循环扫描  
**修复**: `run_intraday()` 内部加循环，间隔由数据源能力决定

### 12. 策略信号与回测逻辑不同步
**现状**: Scanner里的选股条件和回测引擎的 `_build_strategy_filter_conditions` 是两套代码  
**问题**: 回测赚钱的参数，实盘可能用错参数  
**修复**: Scanner复用回测引擎的策略条件函数

### 13. 没有盘前集合竞价分析
**现状**: 9:15-9:25集合竞价数据完全空白  
**问题**: 龙头首板策略核心就是竞价选股，缺这个策略废一半  
**修复**: 必盈有集合竞价数据接口(待确认)，或用9:25的开盘价近似

### 14. 没有盘中异动监控
**现状**: 只做定时扫描，没有异动触发  
**问题**: 突然拉升/跌停打开/量比突变 → 来不及反应  
**修复**: 基于5分钟K线或实时行情检测异动条件

### 15. 信号推送只推飞书/企业微信
**现状**: `SignalPusher` 支持多渠道但配置复杂  
**问题**: 实盘需要确保信号必达  
**修复**: 增加WebSocket推送(前端实时显示) + 推送失败重试

### 16. 没有资金管理（银证转账等）
**现状**: 初始资金硬编码100万  
**问题**: 实盘需要对接真实资金  
**修复**: 这是QMT/掘金券商API的责任，框架层面只需留接口

### 17. 没有回测→实盘参数校验
**现状**: 回测参数和实盘参数可能不一致  
**问题**: 回测用了不切实际的参数(如0滑点、无涨跌停限制)  
**修复**: 实盘模式启动时自动校验参数合理性

## 📊 架构层面的问题

### 18. 两套Broker体系不统一
- `SimulatedBroker` (nodes/market_monitor/broker.py): Scanner用的
- `SimTradingEngine` (core/managers/sim_trading_engine.py): 回测用的
- `BaseTradeGateway` (core/managers/live/trade_gateway.py): 框架设计的
- `GmBroker` (nodes/market_monitor/gm_broker.py): 掘金用的

**4套Broker，接口不统一**，实盘对接QMT时不知道该继承谁

**建议**: 统一为 `BaseBroker` 基类，4个实现：SimulatedScanner / SimulatedBacktest / GmPaper / QmtLive

### 19. 持仓模型有3种
- `broker.py:Position` (Scanner用)
- `position_manager.py:Position` (实盘用)
- 回测引擎的持仓数据结构(又一种)

**3种Position，字段不统一**，数据在各模块间传递需要转换

**建议**: 统一为 `UnifiedPosition` 数据类

## 💡 关于3个数据源的使用策略

| 场景 | 用哪个 | 原因 |
|------|--------|------|
| 涨停/跌停/炸板池 | **必盈** | 数据最全(封板资金/连板/炸板次数) |
| 实时行情(全市场扫描) | **必盈**(免费版够) | 无IP限制，稳定 |
| 个股五档盘口 | **必盈** | 批量五档，量脉只有1只/次 |
| 分钟K线 | **量脉** | 必盈免费版无分钟K线 |
| 资金流向 | **量脉** | 必盈URL待确认 |
| 实盘交易 | **掘金/QMT** | 量脉和必盈都是纯数据 |

建议: **必盈做主力数据源，量脉做备用和补充(分钟K/资金流)**
