## 一、体系架构总览

### 卖出决策优先级链（从高到低）

```
┌─────────────────────────────────────────────────────────────┐
│  主循环 check_stop_loss_take_profit (5分钟/轮)              │
├─────────────────────────────────────────────────────────────┤
│  1. 追踪止损    │ current ≤ trailing_stop_price            │
│  2. 固定止损    │ profit_pct ≤ -stop_loss_pct              │
│     ├─ 跳空止损 │ 开盘价 < 止损价 → 分级观察期             │
│     └─ 普通止损 │ 盘中价 < 止损价                          │
│  3. 止盈       │ profit_pct ≥ take_profit_pct              │
│  4. 冲高回落   │ _check_intraday_rules                     │
│     ├─ 冲高回落 │ 开涨≥2%+回落≥1.5%/5%                    │
│     ├─ 利润保护 │ 开涨≥2%+现涨≥2%+回落                    │
│     ├─ 利润锁定 │ 冲高≥6%+回撤≥2.5%+仍盈≥2%              │
│     ├─ 高开即卖 │ 首板专属: 开涨≥2%                       │
│     └─ 龙头低利 │ 龙头低吸: 5天+盈<3%                     │
├─────────────────────────────────────────────────────────────┤
│  风控线程 check_stop_loss_only (1秒/轮, 仅止损)            │
├─────────────────────────────────────────────────────────────┤
│  1. 跌停挂起   │ 跌停不可卖 → pending_sells               │
│  2. 固定止损   │ 含跳空观察期                              │
│  3. 追踪止损   │ trailing stop                             │
│  (不检查止盈/冲高回落/超时)                                │
├─────────────────────────────────────────────────────────────┤
│  legacy 路径额外检查                                        │
├─────────────────────────────────────────────────────────────┤
│  5. 超时强卖   │ days_held ≥ max_hold_days                │
│  6. 移动止损   │ trailing已激活 + profit < 0              │
└─────────────────────────────────────────────────────────────┘
```

### 两条执行路径

| 路径 | 频率 | 检查内容 | 触发场景 |
|---|---|---|---|
| **主循环** | 5分钟/轮 | 全量（止损+止盈+冲高回落+超时） | scanner._check_positions() |
| **风控线程** | 1秒/轮 | 仅止损（固定+追踪+跌停） | risk_loop_runner → check_stop_loss_only |

## 五、问题诊断与评估

### ✅ 设计合理的部分

1. **跳空止损分级观察期** — 14笔历史数据验证，微跳75%可恢复，大跳100%下跌，分级合理
2. **策略差异化参数** — 每个策略有独立的止损/止盈/持仓天数，不是一刀切
3. **追踪止损兜底机制** — `stop_price = max(raw_stop, fixed_stop)` 确保追踪止损不会低于固定止损
4. **跌停挂起+恢复** — pending_sells 机制完善，跌停恢复后自动执行
5. **v2.9.116高盈利紧缩** — 盈利≥8%收紧到3%，解决"赚6-8%被追踪止损吃掉大部分"的问题

### ⚠️ 需要关注的问题

#### P1: 追踪止损激活阈值过低（2%）

**现状**: 半路追涨 trailing_stop_pct=0.02，即盈利≥2%就激活追踪止损

**问题**: 
- 激活后回撤容忍=6%（5%base+1%offset）
- 从高点回撤6%在2-5%盈利区间就触发了
- 37%的追踪止损在0-3%盈利时触发，等于刚赚一点就被保护性卖出

**评估**: 激活阈值2%是V72回测验证的参数，但回测时追踪止损逻辑可能与实盘不完全一致。当前看**不算bug**，但可考虑提高到3-5%。

#### P2: 止盈触发率低（5%）

**现状**: 半路追涨止盈12%，但3/56=5%触发率

**问题分析**:
- 止盈12%意味着价格需从买入价上涨12%+
- 但追踪止损在盈利2%就激活，回撤6-8%就卖出
- 大部分股票在6-8%就到顶回落，触发追踪止损而非止盈
- v2.9.116紧缩后（≥8%回撤3%），8%+的盈利会更快被锁定

**评估**: 这是**设计选择**而非bug。止盈12%是"安全网"，实际退出靠追踪止损。v2.9.116的紧缩逻辑已部分解决。

#### P3: 移动止损逻辑在legacy路径中独立存在

**现状**: `position_checker.py` legacy路径有一个独立的"移动止损"检查（trailing已激活+profit<0），这与`_check_trailing_stop`的逻辑重叠。

**评估**: 不算bug但有冗余。移动止损是追踪止损的补充场景（盈利后回撤到亏损），`_check_trailing_stop`的stop_price兜底到固定止损价已经覆盖了这个场景。

#### P4: quick路径不检查止盈和冲高回落

**现状**: `check_stop_loss_only`只检查固定止损+追踪止损+跌停

**评估**: 这是**设计选择**。quick路径1秒/轮，只做最紧急的止损检查。止盈和冲高回落由5分钟主循环处理。在快速下跌场景中这是合理的——先保护本金，再考虑锁利。

#### P5: _get_market_bread 刚实现（v2.9.116补全）

**现状**: v2.9.115加了竞价过滤逻辑但_get_market_bread未定义，v2.9.116补全

**评估**: 已修复。主路径从realtime_cache算平均pct_chg，fallback从sentiment算涨跌家数比。但精度有限——不是真正的指数涨幅，是全市场平均。开盘初期（9:30-9:35）数据量可能不足。

### ❌ 已修复的bug

| bug | 版本 | 影响 |
|---|---|---|
| strategy_scorer._build_signal_from_row NameError | v2.9.116修复 | 每轮扫描丢失信号 |

## 六、改进建议（按优先级）

### P0: 无（当前体系无致命问题）

### P1: 可选优化

1. **追踪止损激活阈值可调高到3-5%**
   - 当前2%激活太早，69%在0-6%盈利被锁定
   - 但需回测验证，可能降低保护效果
   - 建议: A/B测试 trailing_stop_pct=0.03 vs 0.05

2. **开盘初期market_bread精度提升**
   - 当前从realtime_cache算平均pct_chg
   - 可考虑直接获取上证指数/沪深300实时涨幅
   - 东方财富push2支持指数行情(secid=1.000001)

3. **追踪止损日志增强**
   - 当前logger.debug级别太多，盘中排查困难
   - 建议激活/触发时用logger.info，其他保持debug

### P2: 长期演进

1. **止盈线动态化** — 根据市场情绪调整：强势市场12%→15%，弱势→8%
2. **追踪止损分时段** — 开盘30分钟内用更紧的回撤（波动大但反转也快）
3. **回测验证v2.9.116紧缩** — 收集1-2周实盘数据后回测对比

## 七、结论

当前止盈止损体系**整体设计合理**，经过v2.9.107-v2.9.116的持续修复，核心问题已解决：

- ✅ 所有卖出路径统一审计（risk_decisions）
- ✅ 跳空止损竞价过滤已生效（_get_market_bread实现）
- ✅ 高盈利紧缩保护（≥8%回撤3%）
- ✅ 信号生成不再报错（trade_date参数修复）

**主要风险点**是追踪止损激活过早(2%)导致微利被锁，但这是回测验证的参数，需要更多数据才能判断是否调整。v2.9.116的高盈利紧缩是对此问题的第一步缓解。
