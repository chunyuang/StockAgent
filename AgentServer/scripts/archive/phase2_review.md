# Phase2 修复全面审查报告

## 1. 修改概述

### 已完成的修改
1. **新增盘中可观测因子**：
   - `intraday_max_rise_pct`: 盘中最高价相对昨收涨幅
   - `intraday_open_rise_pct`: 开盘价相对昨收涨幅

2. **策略筛选条件替换**：
   - 半路追涨：`pct_chg` → `intraday_max_rise_pct` / `intraday_open_rise_pct`
   - 涨停开板：`pct_chg >= 0` → `intraday_max_rise_pct >= 0`

3. **因子计算位置**：
   - `factor_engine.py`: 在回测模式和实盘模式都添加了因子计算
   - 确保 `high`, `open`, `pre_close` 在 MongoDB projection 中

## 2. 合理性分析

### 2.1 因子计算逻辑合理性 ✅

**公式正确性**：
```python
intraday_max_rise_pct = (high - pre_close) / pre_close * 100
intraday_open_rise_pct = (open - pre_close) / pre_close * 100
```
- ✅ 使用百分比格式（与 `pct_chg` 一致）
- ✅ 处理除零错误：`.replace(0, np.nan)`
- ✅ 在回测和实盘模式都计算

**数据可得性**：
- ✅ `high`, `open`, `pre_close` 在日线数据中都有
- ✅ 实盘中可实时观测（开盘价、最高价、昨收价）

### 2.2 未来函数消除合理性 ⚠️

**半路追涨策略**：
- 原条件：`pct_chg >= min_rise_pct*100` 且 `pct_chg <= max_rise_pct*100`
- 新条件：`intraday_max_rise_pct >= min_rise_pct*100` 且 `intraday_open_rise_pct <= max_rise_pct*100`

**分析**：
1. **进步**：不再依赖收盘涨幅，避免了未来函数
2. **逻辑变化**：
   - 从"收盘涨幅在2-5%" → "盘中最高涨幅≥2% 且 开盘涨幅≤5%"
   - 这改变了策略逻辑：原来要求收盘涨幅，现在要求开盘不超5%、盘中能冲高2%

**⚠️ 潜在问题**：
- `intraday_max_rise_pct >= 2%` 但 `intraday_open_rise_pct <= 5%` 的股票，可能在收盘时回落
- 原策略是"稳涨"，新策略是"冲高回落也能接受"
- 这可能会增加交易次数但降低胜率

### 2.3 单位一致性检查 ✅

**检查结果**：
- 新因子：百分比格式（`* 100`） ✅
- 筛选目标：`min_rise_pct * 100`（百分比） ✅
- 与 `pct_chg` 单位一致 ✅

**对比历史教训**：
- 2026-05-03记忆：`pullback_pct`存负数，`rise_after_limit_down`存百分比
- 本次：两个新因子都明确使用百分比，与目标单位匹配 ✅

### 2.4 涨停开板策略合理性 ⚠️

**修改**：`pct_chg >= 0` → `intraday_max_rise_pct >= 0`

**分析**：
- ✅ 消除了未来函数
- ⚠️ 逻辑变化：从"收盘不跌" → "盘中最高价不跌破昨收"
- 这更宽松：盘中冲高回落收盘下跌也可能被选中
