## 一、当前扫描方案

### 1.1 架构：单循环全流程

```
┌─────────────────── scan_once主循环 ───────────────────┐
│                                                         │
│  Step1 行情获取(东方财富5400只) ──── 6~10秒 ← 瓶颈!  │
│  Step2 因子合并(MongoDB历史) ──────── <1秒             │
│  Step3 持仓检查(止损止盈) ─────────── <1秒             │
│  Step4 策略筛选+异动检测 ──────────── 1~2秒            │
│  Step5 9层管道(L1→L9) ────────────── 1~2秒            │
│  Step6 信号更新+买入执行 ──────────── <1秒             │
│  Step7 持久化(MongoDB写入) ────────── <1秒             │
│                                                         │
│  总耗时: 10~12秒/轮                                     │
│  间隔: 120~300秒(分时段)                                │
│  实际周期: 130~312秒/轮                                  │
└─────────────────────────────────────────────────────────┘
```

### 1.2 扫描类型与触发

| 类型 | 触发方式 | 频率 | 数据源 | 产出 |

| **全市场主扫** | scan_once主循环 | 2~5分钟/轮 | 东方财富5400只快照 | 策略信号(半路追涨/首板打板/龙头低吸/跌停翘板) |

### 1.4 9层管道

```
全市场5400只
  ↓ L1 强制空仓(大盘极端) ─── 极少触发
  ↓ L2 特殊时期(节假/月末) ── 偶尔
  ↓ L3 情绪周期(仓位系数) ──── 持续生效(当前50%仓位)
  ↓ L4 盘前预选(ST/次新/低流) ~10%淘汰
  ↓ L5 竞价过滤(极端竞价) ──── ~10-20%淘汰
  ↓ L6 策略量能(涨幅/量比/换手) 主拦截层~70%
  ↓ L7 综合排序(优先级+截断10) 少量
  ↓ L8 仓位控制(情绪×单票×总仓) 按仓位
  ↓ L9 买入执行(T+1/成交概率) 首板受限于成交概率
  → 0~5只买入信号
```

## 二、优化方案

### 方案A：修复早盘间隔 + 防盘中重启（P0）

**问题**：
1. 旧代码无分时段逻辑 → 早盘300秒(应120秒)
2. 盘中Web进程重启4次 → 8分钟扫描空白+风控空白

**修复**：
- 新代码已包含分时段(下次启动生效)
- scanner独立于Web进程，或重启后跳过盘前准备快速恢复

**效果**：早盘9:30-10:00从4轮→15轮，信号捕获率↑3倍

**改动量**：小(1个配置确认+1个重启保护)

---

### 方案B：启用TieredScanner（P1）

**架构**：三级独立asyncio.Task并行

```
┌─── L1 全市场初筛 ───┐   ┌─── L2 候选池策略筛选 ───┐   ┌─── L3 持仓止损止盈 ───┐
│  间隔: 5分钟         │   │  间隔: 30秒              │   │  间隔: 5秒            │
│  数据: 东财5400只    │   │  数据: L1候选池(50~200只)│   │  数据: 持仓+信号股     │
│  逻辑: 涨幅>3%       │   │  逻辑: 策略筛选+9层管道  │   │  逻辑: 止损/止盈/冲高  │
│       +量比>1.5      │   │       +信号更新+买入执行  │   │       +回落检测        │
│  产出: 候选池        │→  │  产出: 买入信号          │   │  产出: 卖出信号        │
│  耗时: 6~10秒/轮     │   │  耗时: <1秒/轮           │   │  耗时: <0.5秒/轮       │
└──────────────────────┘   └──────────────────────────┘   └────────────────────────┘
```

**关键配置**：
```python
L1_INTERVAL = 300      # 5分钟(全市场)
L2_INTERVAL = 30       # 30秒(候选池) ← 核心提升!
L3_INTERVAL = 5        # 5秒(持仓)
L1_MIN_PCT_CHG = 3.0   # 涨幅>3%
L1_MIN_VOLUME_RATIO = 1.5  # 量比>1.5
L1_MIN_FLOAT_MV = 10.0    # 流通市值>10亿
```

**早盘效果对比**：

| 指标 | 当前scan_once | TieredScanner |
|------|--------------|---------------|
| 9:30-10:00全市场扫描 | 4轮(5分钟/轮) | 6轮(5分钟/轮, L1) |
| 9:30-10:00策略筛选 | 4轮(5分钟/轮) | **60轮(30秒/轮, L2)** |
| 止损检查 | 1秒/轮(风控线程) | 5秒/轮(L3) |
| 单轮策略筛选耗时 | 10~12秒(含行情) | **<1秒**(只扫候选池) |

**风险**：
- TieredScanner和现有scan_once可能双重扫描 → 需禁用scan_once或设互斥
- L2依赖L1候选池 → L1首次运行前L2空转(需等5分钟)

**改动量**：中(设置`use_tiered_scanner=True`+禁用scan_once+测试)

### 方案C：行情预取独立线程（P1）

**架构**：分离行情获取和策略筛选

```
┌─── 行情预取线程 ──────────┐   ┌─── scan_once策略筛选 ───┐
│  间隔: 30秒               │   │  间隔: 120秒(分时段)     │
│  数据: 东方财富5400只     │   │  数据: 读realtime_cache  │
│  产出: realtime_cache     │→  │  耗时: <2秒(无行情等待)  │
│  耗时: 6~10秒/次          │   │  产出: 信号+买入         │
│  降级: TTL缓存(<5s用缓存) │   └──────────────────────────┘
└────────────────────────────┘
```

**效果**：
- scan_once从10~12秒→2秒(去掉行情等待)
- 同样120秒间隔，但每轮快5倍
- 可支持更密集扫描(60秒/轮也不卡)
- 行情数据始终新鲜(30秒刷新一次)

**风险**：
- 线程安全：realtime_cache读写需加锁
- 行情获取失败时cache过期 → 需TTL+降级

**改动量**：中(拆线程+加锁+测试)

    # 3. pullback_pct = (今天收盘 - 涨停日收盘) / 涨停日收盘
