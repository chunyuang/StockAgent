## 二、9层筛选管道

| 层 | 名称 | 逻辑 | 拦截效果 |
|----|------|------|----------|
| L1 | 强制空仓 | 涨停≤10或跌停≥80或大盘跌≥3% → 清仓 | 极少触发 |
| L2 | 特殊时期 | 节假日/会议/月末 → 降仓 | 偶尔 |
| L3 | 情绪周期 | 情绪<40冰点→25%仓位; 40-55震荡→50%; 55-70分化→70%; ≥70高潮→100% | **持续生效，当前42-50分=50%仓位** |
| L4 | 盘前预选 | 排除ST/退市/次新(<60天)/低流动(<500万) | ~10% |
| L5 | 竞价过滤 | 排除极端竞价(高开>7%/低开<-5%) | ~10-20% |
| L6 | 策略量能 | 复用回测策略筛选(涨幅/量比/换手/市值) | **主拦截层** |
| L7 | 综合排序 | 优先级+去重+截断10只 | 少量 |
| L8 | 仓位控制 | 情绪×特殊×单票35%×总仓50-70% | 按仓位情况 |
| L9 | 买入执行 | T+1检查/跳空止损/成交概率模拟 | 首板受成交概率限制 |

## 四、扫描频率问题 — 核心发现

### 4.1 配置 vs 实际

| 时段 | 配置间隔 | **实际间隔** | 原因 |
|------|----------|-------------|------|
| 9:30-10:00 | 120秒(2分钟) | **300秒(5分钟)** | 🔴 **BUG** |
| 10:00-11:00 | 180秒(3分钟) | **300秒(5分钟)** | 🔴 同上 |
| 10:14后(重启) | 180秒 | 185秒 | ✅ 正常 |
| 11:00-11:30 | 300秒 | 300秒 | ✅ 正常 |
| 13:00-14:00 | 300秒 | 300秒 | ✅ 正常 |
| 14:00-14:30 | 180秒 | 180秒 | ✅ 正常 |

### 4.2 早盘5分钟的根因

**`_get_dynamic_scan_interval()`返回120秒，但`_scan_loop_trading()`的间隔判断逻辑有bug**：

```python
# scan_loop_runner.py L166-167
elapsed = time.time() - last_full_scan
current_interval = self._get_dynamic_scan_interval()  # 返回120秒
if elapsed >= current_interval:
    await self.scan_once(trade_date)  # 执行全量扫描
```

逻辑看起来正确，但实际间隔300秒。**根因**：

1. 09:30:34首轮scan_once耗时11秒 → 09:30:45完成
2. 非全量轮进入`else`分支 → sleep(check_interval=30秒) → 刷新行情
3. 但`check_interval`是30秒，每30秒醒来检查`elapsed >= 120`
4. 理论上120秒后应该触发第二轮 → **但实际是300秒**

**进一步排查**：10:14 risk_loop异常重启后，间隔变成185秒(接近3分钟配置)，说明`_get_dynamic_scan_interval()`在重启后生效了。**可能是首轮scan_once完成后last_full_scan未正确更新，或者scan_once内部有额外的sleep**。

### 4.3 早盘扫描密度影响

| 时段 | 信号占比 | 扫描轮数(7/8) | 密度 |
|------|----------|--------------|------|
| 9:15-9:30竞价 | 32% | 盘前扫描 | OK |
| **9:30-10:00早盘** | **27%** | **仅4轮** | ❌ **严重不足** |
| 10:00-10:30 | — | 4轮 | ❌ 不足 |
| 10:30-11:30 | 11% | 12轮 | OK |
| 13:00-14:00 | 19% | ~12轮 | OK |

**9:30-10:00是交易第二高峰(27%信号)，但仅4轮扫描，平均7.5分钟/轮！**

如果按配置120秒执行：30分钟应15轮，信号捕获率可提升3倍。

## 五、信号漏斗 — 修正版

### 5.1 各策略漏斗(修正anomaly理解)

| 策略 | 信号数 | 买入数 | 转化率 | 说明 |
|------|--------|--------|--------|------|
| **halfway_chase** | 626 | 68 | 10.9% | ✅ 唯一主力策略 |
| **first_limit_up** | 109 | 7 | 6.4% | 打板成交概率限制 |
| **anomaly_surge** | 1,528 | ~25 | ~1.6% | ⚠️ 异动标签，非独立策略，买入归入halfway_chase |
| **anomaly_strong** | 149 | ~5 | ~3.4% | 同上 |
| **limit_down_qiao** | 141 | 0 | 0% | ❌ 信号被管道拦截 |
| **dragon_head** | 0 | 0 | — | ❌ **0信号** |
| **limit_up_open** | 217 | 0 | 0% | 已禁用 |

**anomaly修正**：anomaly不是独立策略，是异动检测标签。同一只票既产生anomaly信号又产生halfway_chase信号，买入时strategy写halfway_chase。所以anomaly"0成交"是统计口径问题，实际有25-30只通过halfway_chase买入。

### 5.2 dragon_head 0信号根因

**筛选条件9条**，其中关键两条：

```
pullback_days >= 1   → 实盘补0 → 0 >= 1 → False → mask=False
pullback_pct <= -0.05 → 实盘补0 → 0 <= -0.05 → False → mask=False
```

**pullback_days和pullback_pct在实盘中无法实时计算**（需多日历史），strategy_scorer补0后，fail-closed模式下条件不满足→0候选。

**这是设计问题**：龙头低吸需要"连板后回调"的回调幅度和天数，这两个字段需要从历史K线实时计算，但当前merge_factors不计算它们。

### 5.3 limit_down_qiao 0成交根因

141个信号中65个new+52个blocked+24个skipped。new状态的信号layer_trace显示L1-L8全部通过，但最终0个executed。

**可能原因**：L8仓位控制(情绪50%→总仓上限50%)已满，或L9执行层T+1/成交概率限制。

## 六、优化方案

### 方案A：修复早盘扫描间隔bug（P0，立即）

**问题**：配置120秒但实际300秒
**排查方向**：
1. scan_once完成后`last_full_scan`是否正确更新
2. `_scan_loop_trading`中`elapsed >= current_interval`的判断时序
3. 是否有其他sleep或await导致间隔拉长

**预期效果**：9:30-10:00从4轮→15轮，信号捕获率提升3倍

### 方案B：启用TieredScanner（P1，1-2天）

**改动**：`use_tiered_scanner=True` + 注册L1/L2/L3回调

**效果**：
- L2候选池30秒/轮 → 早盘30分钟60轮(vs现在4轮)
- 扫描密度提升**15倍**
- L2只扫50-200只(非5400只)，单轮<1秒

**风险**：TieredScanner是独立asyncio.Task，与现有scan_once主循环可能冲突，需确认不会双重扫描

### 方案C：行情预取独立线程（P1，2-3天）

**核心**：分离行情获取(8秒瓶颈)和策略筛选

1. 行情获取：独立线程，每30秒刷新realtime_cache
2. scan_once直接读cache → 从11秒→2秒

**效果**：scan_once快5倍，同样120秒间隔但每轮快得多

### 方案D：dragon_head回调字段实时计算（P2，1天）

**核心**：在merge_factors中计算pullback_pct和pullback_days

```python
# 从近5日K线计算:
# 1. 找到最近一次涨停日(limit_up_count>=1)
# 2. 从涨停日到今天的天数 = pullback_days
# 3. (今天收盘 - 涨停日收盘) / 涨停日收盘 = pullback_pct
```

**效果**：dragon_head从0信号→正常产生信号，理论胜率93.5%的策略参与交易

### 方案E：limit_down_qiao管道拦截排查（P2，半天）

65个new信号0个executed，需逐层排查L8/L9的拦截原因
