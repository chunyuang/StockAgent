# 🚀 StockAgent 使用指南

> 最后更新：2026-07-06 | 覆盖 v2.9.109+ 全部功能

## 📋 平台概述

全自动实盘量化交易系统，从数据采补→因子计算→策略筛选→9层管道→模拟交易→风控→绩效分析→飞书推送，全链路自动化。

## 🖥️ Web 前端

访问地址：`http://<服务器IP>:8000`

### 页面一览

| 路由 | 页面 | 功能 |
|------|------|------|
| `/` | 首页 | 实时行情+持仓+信号+情绪 |

| `/cockpit` | 驾驶舱 | 账户+情绪+策略+风控全景 |
| `/strategies` | 策略管理 | 参数配置+绩效+订阅 |

- **数据获取页**：健康分区分实盘/回测，实盘健康分=100表示所有筛选因子全覆盖
- **交易归档页**：选择交易日查看完整归档，持仓行按盈亏着色（绿盈红亏）
- **持仓监控页**：已平仓逐笔可折叠，买入红底/卖出绿底

### 数据源优先级

| 优先级 | 数据源 | 用途 | 限制 |
|--------|--------|------|------|
| 1 主力 | 东方财富 push2 | 全市场快照(日线+PE/PB) | 无限流，3秒/次 |
| 2 备用 | 搜狐 hisHq | 盘后补采fallback | 无限流 |
| 3 有限 | 量脉 API | 实时盘中/1min K线 | 120次/min，2个IP |
| 4 批量 | Tushare | 全市场批量补 | 5000积分(~4758剩余) |
| 5 涨停 | 必盈 API | 涨停池 | 200次/天 |

### 每日采补链路

```
15:35 盘后: 东方财富(主力) → 搜狐(fallback) → limit_list → lightweight_factor_fill → 验证
07:00 盘前: 检查缺失 → 搜狐补采 → limit_list推算 → 验证
盘中:     实时行情自包含(scanner直接从东方财富push2拉)
每月1号:  Tushare财务因子补算
```

### 单位标准

| 字段 | 单位 | 说明 |
|------|------|------|
| `vol` | 手 | 1手=100股 |
| `amount` | 百元 | 东方财富/搜狐需转换 |
| `turnover_rate` | 百分数 | 如25.04表示25.04% |
| `circ_mv` | 万元 | ak_full中；daily_basic中为亿元 |
| `volume_ratio` | 小数 | 如1.23表示量比1.23 |

> ⚠️ 详见 `AgentServer/docs/DATA_FIELD_UNITS.md`

## 🧮 因子体系

### 因子分层（关键！影响实盘vs回测健康分）

| 层级 | 因子组 | 因子示例 | 缺失影响 | 参与健康分 |
|------|--------|----------|----------|-----------|
| **筛选条件** | basic | `pct_chg`, `pre_close`, `turnover_rate` | **mask=False，不买** | ✅ 实盘 |
| **筛选条件** | technical_ma | `ma5`, `ma10`, `ma20`, `ma60` | 条件跳过 | ✅ 实盘 |
| **筛选条件** | volume | `volume_ratio`, `circ_mv` | 条件跳过 | ✅ 实盘 |
| **筛选条件** | limit | `first_limit_up`, `is_limit_up`, `limit_up_count` | 首板/跌停策略失效 | ✅ 实盘 |
| **仅展示** | technical_talib | `macd`, `rsi_6`, `boll_upper`, `atr` | 信号描述缺字段，**不影响筛选** | ❌ 仅回测 |

**实盘健康分** = 实盘因子(4组) + 新鲜度 + 数据源可用
**回测健康分** = 全部因子(5组) + 新鲜度 + 数据源可用

> TALib指标(MACD/RSI/BOLL/ATR)仅用于信号描述文本展示，不参与任何策略筛选条件。回测时由`factor_engine`实时计算，不依赖MongoDB预存。盘后由`lightweight_factor_fill.py`补算。

## 🎯 策略体系

### 当前策略

| 策略 | 说明 | 筛选条件关键因子 |
|------|------|-----------------|
| 首板打板 | 涨停首板买入 | `first_limit_up`, `turnover_rate`, `circ_mv` |
| 涨停开板 | 涨停后开板买入 | `is_limit_up`, `open_times` |
| 龙头低吸 | 龙头股回调低吸 | `pullback_pct`, `pullback_days`, `limit_up_count` |
| 跌停翘板 | 跌停板翘板买入 | `is_limit_down`, `circ_mv` |
| 半路追涨 | 盘中强势追涨 | `pct_chg`, `volume_ratio` (当前不可用) |

### 9层管道

```
L1 强制空仓 → L2 特殊时期 → L3 情绪 → L4 盘前 → L5 竞价 → L6 策略 → L7 排序 → L8 仓位 → L9 执行
```

### 交易流程7步

```
Step1 行情获取 → Step2 因子合并(merge_factors) → Step3 策略筛选(apply_strategies)
→ Step4 9层管道(filter_pipeline) → Step5 持仓检查(止损止盈)
→ Step6 价格同步 → Step7 持久化
```

### 涨跌停阈值（按板块区分）

| 板块 | 涨跌停幅度 | ST幅度 |
|------|-----------|--------|
| 主板(60/000) | 10% | 5%(2026-07-06新规: ST主板10%) |
| 创业板(300) | 20% | 20% |
| 科创板(688) | 20% | 20% |
| 北交所(8/4) | 30% | 30% |

## 🔄 定时任务

### 系统 Cron

```bash
# 盘后数据更新(周一至周五 15:15)
15 15 * * 1-5 cd /root/.openclaw/workspace/StockAgent && bash AgentServer/scripts/daily_data_update.sh
```

### OpenClaw Cron（关键任务）

| 任务 | 时间 | 脚本 | 说明 |
|------|------|------|------|
| 盘后采补 | 15:35 | `eastmoney_daily_bar` + `basic` + `lightweight_factor_fill` | 东方财富→搜狐fallback→涨停池→因子补算→验证 |
| 盘前自愈 | 07:00 | 检查缺失→搜狐补采→limit_list推算 | 确保开盘前数据就绪 |
| 因子影响审查 | 16:00 | `factor_impact_audit.py` | 8维度: 计算正确性/值域/策略一致性/派生因子等 |
| 交易数据审查 | 16:10 | `trading_data_audit.py` | 6维度: positions.mv/账户等式/equity单调等 |
| 数据单位验证 | 16:40 | `validate_data_units.py` | 检查MongoDB数据单位是否正确 |
| 使用侧一致性 | 周一20:00 | 使用侧审查 | circ_mv单位/PE-PB/策略参数vs代码 |

## ⚠️ 已知限制

| 限制 | 说明 | 影响 |
|------|------|------|
| 量脉IP限制 | Token绑定2个IP，服务器动态IP可能429 | 实时行情fallback到东方财富 |
| TALib盘后补算 | 盘后cron跑后才写入MongoDB | 盘中信号描述缺字段，不影响筛选 |
| daily_basic可能缺 | 东方财富盘后偶尔失败 | 手动补: `eastmoney_daily_basic.py --date` |
| 半路追涨不可用 | 策略条件不满足 | 不产生信号 |
| 模拟交易 | 非真实券商对接 | 无实盘执行能力 |

## 📞 问题排查

### 健康分不满分

1. **实盘健康分<100**：实盘必需因子缺失 → 运行 `lightweight_factor_fill.py` 补算
2. **回测健康分<实盘**：TALib指标未补算 → 同上，或等盘后cron自动跑
3. **新鲜度扣分**：最近交易日数据未采补 → 运行 `eastmoney_daily_bar.py --date`
