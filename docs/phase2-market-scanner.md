# Phase 2: 超短量化市场监听

## 核心理念

**不是传统"市场监听"**——不是看大盘指数、宏观新闻、资金流向。
**是超短策略的实时信号扫描器**——把回测引擎的选股逻辑搬到实时数据上跑。

回测做了什么：遍历5000只股票×每个交易日 → 算因子 → 筛选 → 买入 → 卖出
实盘要做什么：**每个交易日的9:30~15:00**，用实时数据重复同样流程

## 与回测的区别

| | 回测 | 实盘监听 |
|--|------|---------|
| 数据 | MongoDB历史日线 | 量脉实时行情 |
| 因子 | 预计算读MongoDB | 实时计算(简化版) |
| 筛选 | _build_strategy_filter_conditions | **完全复用** |
| 执行 | 虚拟账户结算 | SimTradingEngine |
| 频率 | 每日1次 | 盘中每1~5分钟 |
| 信号 | 静态列表 | 动态增减(开板/回封) |

## 关键问题: 实时因子计算

回测因子依赖120天历史数据(MA/MACD/RSI等)。盘中只能用:
- **可以直接从实时行情获取**: pct_chg, volume_ratio(量比), turnover_rate, circ_mv
- **可以用当日已有数据估算**: is_limit_up(涨幅≥9.5%), limit_up_count
- **需要历史数据但可缓存**: ma5(缓存前4天+当日), rsi(缓存前N天)

**策略: 混合模式**
- 日级因子(昨收计算好的) → 从MongoDB读取(盘前预加载)
- 实时因子(今日盘中变化) → 从量脉实时行情提取
- 合并后传入策略筛选

### 3. API端点

- `GET /api/v1/scanner/status` — 扫描器状态
- `POST /api/v1/scanner/start` — 启动扫描
- `POST /api/v1/scanner/stop` — 停止
- `GET /api/v1/scanner/signals` — 当前信号
- `GET /api/v1/scanner/positions` — 实时持仓
- `GET /api/v1/scanner/timeline` — 今日交易时间线
- `WS /api/v1/scanner/ws` — WebSocket实时推送
